# Competitor intelligence

## Goal

Competitor research tests whether a complaint cluster supports a new product, a narrow feature, a service, an integration, or no build at all.

The system cannot truthfully promise to find every competitor. It must document the search method, covered categories, sources, observation date, and remaining gaps.

## Competitor graph

Each opportunity maps six relationship types.

### Direct competitor

Targets the same user and job with a similar product mechanism.

### Adjacent competitor

Solves part of the job or targets a neighboring segment.

### Platform-native solution

A feature inside an operating system, app store, major platform, or incumbent product.

### Substitute

A different product category, agency, freelancer, internal team, spreadsheet, script, template, or manual process.

### Complement

A product the proposed app must integrate with or depend on.

### Historical signal

A discontinued, acquired, pivoted, or failed product that reveals demand, cost, access, or business-model risk.

## Discovery method

For every opportunity, search by:

- canonical problem phrase
- desired outcome
- user segment and job
- current workaround
- direct app names
- category names
- “alternative to” language
- comparison pages
- app stores and software directories through approved access
- repositories and package registries
- platform marketplaces
- recent launch sources
- product documentation
- changelogs and release notes
- pricing pages
- customer review sources
- community discussions

The method should expand from the job, not only from the first named competitor.

## Complaint research for competitors

For each important competitor, run the same complaint pipeline used for seed apps.

Compare:

- complaint frequency
- complaint severity
- unique authors
- cluster distribution
- velocity
- platform distribution
- version context
- response or workaround patterns
- source coverage

Do not compare raw counts when source coverage differs sharply.

## Feature matrix

A feature matrix should focus on decision-relevant capabilities.

Suggested rows:

- core workflow coverage
- setup time
- required permissions
- supported platforms
- integrations
- import and export
- collaboration
- automation
- privacy controls
- offline support
- accessibility
- admin and enterprise controls
- pricing structure
- data ownership
- API or developer access
- support quality

Mark each cell with a source and date. Use `unknown` when evidence is missing.

## Gap analysis

A credible gap has four parts:

1. Users repeatedly experience the problem.
2. Existing options fail for a specific reason.
3. The proposed mechanism can address that reason.
4. The target users can discover, trust, and pay for the result.

Common gap types:

- underserved segment
- missing workflow integration
- poor cross-platform support
- high setup cost
- complex enterprise product serving a small-team need
- privacy or local-first need
- accessibility gap
- regional or language gap
- pricing mismatch
- weak reliability
- data portability gap
- poor automation
- slow feedback loop

## Build challenge

Before recommending a new app, the report must answer:

- Could a template, integration, script, browser extension, or service solve this faster?
- Could an existing competitor add the feature easily?
- Does the proposal rely on one platform that can block it?
- Is distribution controlled by the same incumbent being challenged?
- Is the product a feature that lacks repeat use or retention?
- Would the user trust a new provider with the required data?
- Does the opportunity need network effects or proprietary data at launch?

## Competitive pressure score

Competitive pressure is separate from complaint volume.

It can include:

- number of strong direct competitors
- incumbent distribution strength
- feature parity
- switching cost
- free alternatives
- platform-native replacement risk
- pace of recent releases
- ease of copying the proposed mechanism
- access to data
- trust requirements

High competitive pressure does not always kill an opportunity. It changes the product wedge and score.
