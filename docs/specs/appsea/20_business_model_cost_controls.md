# Business model and cost controls

## Customer value

AppSea reduces the cost and uncertainty of finding a software opportunity and preparing it for delivery.

The customer pays for:

- source coverage
- evidence quality
- ranking and comparison
- deep research
- competitor analysis
- machine-readable plans
- repeated monitoring
- team workflow
- compliance and provenance

## Initial customer profiles

### Solo builder

Needs a small number of high-quality opportunities and exportable plans.

### Venture studio

Needs category campaigns, comparison, repeatable research, and many plan packages.

### Product or innovation team

Needs private imports, competitors, evidence review, collaboration, and audit.

### Agent platform or development firm

Needs API, MCP, bulk plan export, and predictable contracts.

## Possible plans

### Explorer

- limited public-source campaigns
- leaderboard access
- limited deep reports
- basic exports

### Builder

- more campaigns
- custom scoring profiles
- plan packages
- MCP and CLI
- monitoring

### Studio

- team workflow
- private imports
- higher budgets
- API access
- multiple workspaces
- advanced comparison

### Enterprise

- SSO
- regional controls
- custom retention
- licensed-source integration
- audit export
- private networking
- dedicated support

Pricing should follow measured source, model, and research cost. Do not set final prices before a cost model and customer interviews.

## Usage units

Possible billing units:

- active research campaigns
- evidence items processed after deduplication
- deep research runs
- plan packages
- monitored opportunities
- premium licensed-source credits
- seats for collaboration
- API and MCP volume

Avoid billing on raw collected posts alone. That rewards noise and makes costs hard to understand.

## Cost drivers

- paid social and search APIs
- licensed data providers
- model inference
- embeddings
- translation
- search indexing
- raw evidence storage
- long report generation
- competitor web research
- support for platform access reviews
- security and compliance

## Cost reduction

- filter with rules before model calls
- deduplicate before embeddings and extraction
- batch model requests
- cache app entities and competitor facts with freshness
- use smaller models for classification
- reserve expensive reasoning for top candidates
- use evidence snapshots to avoid repeated work
- reuse verified competitor records across permitted scopes
- cap deep research candidates
- expire raw data by policy
- show estimated cost before a campaign starts

## Unit economics dashboard

Track:

- cost per campaign
- cost per accepted complaint
- cost per reviewed cluster
- cost per researched opportunity
- cost per published plan
- cost per customer decision
- gross margin by plan
- source-license share
- model share
- storage share

## Go-to-market wedge

A useful first message is:

“Find recurring software problems with evidence, compare the current solutions, and export a build-ready plan.”

Start with builders who already use coding agents but lack reliable product research.

Potential channels:

- developer and founder communities
- coding-agent ecosystems
- venture studios
- product research content
- public opportunity reports with limited evidence excerpts
- integrations with GitHub and agent tools

## Product moat

Weak moat:

- a generic LLM prompt that summarizes complaints
- a simple sentiment dashboard
- one brittle scraper

Stronger moat:

- licensed and policy-aware source coverage
- a high-quality app and competitor graph
- complaint and outcome ontology
- human correction dataset
- ranking calibration
- plan quality and task graph evaluations
- history of what users approved, built, rejected, or archived
- coding-agent integrations
- operational trust

## Commercial risks

- source data cost can dominate revenue
- restricted sources can delay promised coverage
- customers may expect certainty from rankings
- public reports can create copyright or privacy risk
- agent plans can appear valuable before build outcomes are known
- enterprise private data increases security burden

The product should price and message around verified coverage, not universal coverage.
