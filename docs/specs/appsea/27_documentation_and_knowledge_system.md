# Documentation and knowledge system

AppSea uses a layered documentation system.

- product docs describe intended user behavior
- architecture docs describe boundaries and data flow
- agent docs describe operation, memory, skills, and autonomy
- runbooks describe repeatable procedures
- ADRs record accepted technical decisions
- active plans coordinate unfinished implementation
- status docs record current capabilities and gaps
- deep specs preserve full product requirements
- generated catalogs index skills, subagents, and repository structure

Documentation changes with behavior. Accepted plan content is promoted into its durable source, then the plan is archived. A feature is not documented as operational until code and meaningful validation exist.
