# Documentation system

Documentation is part of the implementation.

The source of truth depends on the question:

- current behavior: code and tests
- stable product intent: product docs and deep specs
- architecture: architecture docs and ADRs
- active work: `memory/ACTIVE.md` and active plans
- reusable procedure: skills and runbooks
- historical decision: ADRs and decision memory

Do not leave several active files claiming ownership of the same behavior. Promote accepted plans into the relevant source document, then archive the plan.
