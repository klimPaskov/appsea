# Durable user direction

- Build a product that finds recent complaints about existing applications and converts the strongest repeated problems into new app opportunities.
- Research should be extensive and should include related products, direct competitors, substitutes, workarounds, competitor weaknesses, and contrary evidence.
- Rank possible products on a leaderboard, with the strongest opportunity first.
- Every opportunity should open a curated complaint list and a thorough planning package written for coding agents.
- The website is the first interface. Windows and macOS support should follow through a shared web contract and desktop shell.
- The product should learn from repeated implementation experience by maintaining reusable skills, project guidance, memory, and documentation.
- `AGENTS.md` should grow when stable project rules are learned and should be trimmed when rules become stale or too specific.
- The memory system should preserve useful context between coding sessions in a way similar to long-lived agent memory systems.
- The interface should be extremely simple, calm, and visually polished.
- The leaderboard tab should show only the leaderboard.
- Deep research detail belongs on separate opportunity pages.
- The user expects ambitious planning and strong completion proof, but does not want generic filler or inflated file counts.
